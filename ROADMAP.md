# Public roadmap

This roadmap records intended work, not claims of completed functionality.

## Phase 1 — safety and publication boundary

- Define the Bitcoin-only server capability profile.
- Establish a dedicated PostgreSQL service and isolated identities, sessions, roles, and backups.
- Complete code, dependency, content-rights, and secret-history inventories.
- Decide separate licenses for source code and educational content.

## Phase 2 — public technical baseline

- Import only approved Bitcoin-project source and tests.
- Provide reproducible setup from a clean clone using synthetic data.
- Publish threat model, architecture decisions, and a server-side content allowlist.
- Enable required CI, dependency review, and private vulnerability reporting.

## Phase 3 — learning and identity

- Publish the Foundations, Bitcoin ecosystem, and AI learning surfaces.
- Keep Telegram login independent from TON.
- Evaluate Bitcoin wallet ownership proofs with server-generated, single-use challenges.
- Build an isolated personal learning cabinet without commercial surfaces.

## Phase 4 — nonprofit field readiness

- Optimize for slow and unreliable connections.
- Add educator materials and locally reviewed adaptations.
- Validate privacy-safe proof of learning and aggregate impact reporting.
- Complete independent security, accessibility, recovery, and restore reviews.

## Phase 5 — release

- Publish reproducible prereleases and changelogs.
- Resolve all high-severity security findings.
- Complete an explicit launch review before accepting real-user traffic.

Dates and funding milestones will be added only when owners and evidence are confirmed.
